METHOD AND LIMITS

The original outcome decides.

What a pass means

The candidate returned the expected JSON for every supplied case without changing the input. The included checkout also has varied boundary and delivery cases. This is scoped evidence, not proof that all possible inputs or all pages work.

What stays outside the candidate

Expected results, acceptance decisions, payments and evidence files remain in the host. QuickJS receives only the candidate source and one input at a time. Each case has a fresh context.

What is demonstrated

The included merchant and its broken shipping rule are controlled demo fixtures. Manual checking runs the real sandbox. An example correction is not presented as purchased code. A paid run is verified only after its actual request, receipt, signal commitment and on-chain transfer pass the checks.

What remains a separate test

Repository-wide edits, third-party checkout systems, private customer data and production purchases are outside this first release. A local repair is accepted only for the contract supplied by the operator.

CONTRACT FORMAT

Bring a pure business rule.

A complete JavaScript function, one input per case and plain JSON outputs. No imports, host functions or network access are provided.

{
  "version": 1,
  "name": "A customer-owned outcome",
  "entrypoint": "calculate",
  "specification": "Return the input amount plus one.",
  "cases": [
    {"id": "first", "input": 4, "expected": 5}
  ]
}

Source is capped at 16 KB, contracts at 32 KB and cases at 64. Each input is passed into a new isolated runtime. You own the specification and expected results.

SECURITY

A narrow execution boundary.

Candidate execution

QuickJS compiled to WebAssembly runs the candidate with no host callbacks. It has an 8 MB heap, a bounded stack and an interruption deadline. A separate worker adds a hard deadline. In the local service the worker receives an empty environment.

Private keys

Only the trusted local payment process sees the signer. No key is copied into a candidate, report, browser or repository. The service binds to loopback and rejects unexpected Host and Origin headers.

Evidence and spending

Quotes are single-use. Economic terms are checked again before signing. Authorizations are reserved before payment and remain counted if the request later fails. Receipt hashes identify calls; batched transaction hashes do not identify a call by themselves.

Known limits

The host and contract author are trusted. QuickJS is a dependency, not a formal security proof. The demo order is not a production merchant transaction. Testnet use and independent customer adoption are reported separately.
